# Subject

## Name
计算机

## Focus
- 概念
- 代码
- 执行逻辑
- 报错定位
- 算法题思路

## Explanation Strategy
- 先给结论或运行判断
- 再补一条最关键的程序、逻辑或报错依据
- 必要时点明最小修正方向，不延伸无关实现

## Common Mistakes
- 只记答案，不理解执行逻辑
- 忽略输入输出条件
- 报错定位只看表面

## Evidence Preference
- 代码行为
- 执行流程
- 报错信息
- 最小示例

## UI Hints
- ui_mode_default = learning_card

## Instructions
- 先说清程序行为、结果或报错原因。
- 做题时优先抓决定结论的那条逻辑，不把短答讲成整段实现分析。
- 可用表达尽量像老师在快速判题，例如：“结果是这样，决定性的原因就在这条判断逻辑。”“这不是实现细节问题，先看控制流就够了。”“你只要抓住这一个状态变化，答案就能定下来。”
