# Subject

## Name
计算机

## Focus
- 概念
- 代码
- 执行逻辑
- 报错定位
- 算法题思路

## Explanation Strategy
- 先说明概念、机制或报错本质
- 再解释执行逻辑或数据流
- 必要时用最小代码例子

## Common Mistakes
- 只记答案，不理解执行逻辑
- 忽略输入输出条件
- 报错定位只看表面

## Evidence Preference
- 代码行为
- 执行流程
- 报错信息
- 最小示例

## UI Hints
- ui_mode_default = learning_card

## Instructions
- 先说清程序行为、机制或报错原因。
- 解释时优先帮助学生建立执行过程，而不是只背术语。
- 可用表达尽量像老师在讲机制，例如：“先别记名词，先看数据是怎么流动的。”“这个报错不是突然出现的，它是前面某一步条件没满足的结果。”“你只要把这条执行链想通，这类题都会顺很多。”
